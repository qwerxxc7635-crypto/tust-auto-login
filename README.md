# TUST 校园网自动登录（开机自启版）

天津科技大学校园网（Dr.COM eportal 网页认证）的**无人值守**登录工具。

原项目是带界面的程序，启动后只检测状态、联网要点按钮；这个版本没有界面：
登录 Windows 后自动联网，稳定在线时不打扰你，掉线了自己接上。

只依赖 Python 标准库，单文件，不需要管理员权限。

## 快速开始（两条命令）

在 PowerShell 里进入本目录：

```powershell
# 1) 录入账号（会自动探测当前在线的账号和上网方式，直接回车沿用即可）
python auto_login.py --setup

# 2) 写入开机自启，并立即在后台启动
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

之后每次登录 Windows 自动运行：稳定在线时每 60 分钟检查一次，掉线或异常时每 10 分钟。

## 常用命令

| 命令 | 作用 |
|---|---|
| `python auto_login.py --setup` | 录入 / 修改账号密码 |
| `python auto_login.py --diagnose` | **环境自检**：IP 选择、系统代理、TUN、网关、门户状态 |
| `python auto_login.py --status` | 只查状态，不登录 |
| `python auto_login.py` | 现在手动执行一次（同时解除暂停） |
| `python auto_login.py --watch` | 常驻巡检（开机自启用它） |
| `python auto_login.py --logout` | 注销当前设备，并**暂停**自动登录 |
| `python auto_login.py --resume` | 恢复自动登录 |
| `.\install.ps1 -Uninstall` | 卸载启动项、结束进程（保留凭据） |
| `.\install.ps1 -Uninstall -Purge` | 卸载并清除凭据与日志 |

日志：`%LOCALAPPDATA%\TustAutoLogin\auto-login.log`（超过 512 KB 自动轮转一份 `.log.1`）

```powershell
Get-Content -Tail 20 -Wait "$env:LOCALAPPDATA\TustAutoLogin\auto-login.log"
```

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 / 已在线 / 已暂停 |
| 1 | 登录失败或状态未知（会退避重试） |
| 2 | 未配置账号 |
| 3 | 该 IP 上在线的是别的账号（不抢占） |
| 4 | 网络未就绪 |
| 5 | 需要人工处理（密码或上网方式错误，**已停止重试**） |

## 它怎么判断「要不要登录」

每轮只做三件事：

1. **确认网络**：本机有没有一个属于校园网段的 IPv4、网关 `10.10.102.50:80` 通不通。
   开机瞬间 Wi-Fi 还没关联时它会一直等（默认最多 180 秒），不是固定 sleep。
2. **查本机这个 IP 的会话**：请求 `portal/online_list`，找 `online_ip` 等于本机 IP 的那条。
   结果是**三态**：在线 / 确定离线 / 读不懂。
3. **再决定**：
   - 在线且是自己的账号 → 记「已在线」，**不发登录请求**；
   - 在线但是别的账号 → 记警告，**不抢**；
   - 确定离线 → 才认证；
   - 读不懂 → **不登录**（连续 3 轮仍读不懂才放行一次，且 1 小时内最多一次）。

> 只查「网关上有没有设备在线」是不够的：那样每轮都会重复认证，把自己反复踢下线。
> 判断依据必须是「**本机 IP** 有没有会话」。

## 轻量

- **每轮只发 1 个 HTTP 请求**（在线列表接口已经包含 IP、账号、上线时间，门户页那个判据实测无效，已移除）。
- **自适应频率**：掉线/异常时 10 分钟一次，连续 5 轮稳定在线后自动降到 60 分钟一次。
- **休眠唤醒感知**：分片睡眠并检测时钟跳变，合盖唤醒后立即重新检查，不用等满一轮。
- 实测常驻占用：私有内存约 **16 MB**，20 秒 CPU 时间 **0.09 秒**（基本空转）。
- 只有一个日志、一个凭据文件；日志超 512 KB 自动轮转，长期运行不会涨。

## 和 Clash / Clash Verge 共存

这块是专门处理过的，因为 Clash 的两种模式都会影响联网工具：

| 场景 | 本工具的行为 |
|---|---|
| Clash 开着**系统代理** | 所有请求强制直连（显式禁用 `ProxyHandler`）。网关请求不经过代理，**明文密码不会进代理进程**，也不会出现"代理连不上内网导致登录失败"的怪问题 |
| Clash 开着 **TUN 模式** | TUN 网段 `198.18.0.0/15` 被排除在校园网段之外。若 TUN 抢走了到网关的路由，脚本会改用网卡上的真实校园网地址作为 `wlan_user_ip`，而不是提交 TUN 地址 |
| TUN 抢得太彻底，识别不出来 | 会明确报错并给出处置办法，可用 `--source-ip 10.x.x.x` 手动指定 |
| 你换网段了 | `--campus-cidr 172.16.0.0/12` 之类覆盖默认的 `10.0.0.0/8` |

**推荐做法**：在 Clash 的规则里给 `10.0.0.0/8` 加一条 `DIRECT`（TUN 模式下尤其必要），
这样校园网流量完全不进 Clash，两边互不干扰。改完用 `--diagnose` 确认。

```text
环境自检 v1.1.1
路由出口 IP : 10.131.7.144 → 可用
  候选地址  : 26.192.160.246   不可用（不在校园网段 10.0.0.0/8）
  候选地址  : 10.131.7.144     可用
选定源地址  : 10.131.7.144  自动识别
系统代理    : 无
网关 TCP    : 可达
门户状态    : 已在线（2308****@unicom）
```

## 文件说明

| 文件 | 说明 |
|---|---|
| `auto_login.py` | 主脚本，纯标准库 |
| `install.ps1` | 启动项安装 / 卸载（不需要管理员权限） |
| `%LOCALAPPDATA%\TustAutoLogin\cred.dat` | 账号密码，Windows DPAPI 加密，只有当前用户能解密 |
| `%LOCALAPPDATA%\TustAutoLogin\auto-login.log` | 运行日志，账号已脱敏（`2308****@unicom`） |

## 已知限制

- **改过密码要重跑 `--setup`**。现在的行为是：识别出「密码错误 / 上网方式错误」后**停止访问网关**，
  等 `cred.dat` 更新再自动恢复，不会每分钟撞一次密码、把账号试到锁定。
- **上网方式必须选对**（`@unicom` / `@cmcc` / `@telecom` / 无）。`--setup` 会自动探测并预选。
- **校园网门户改版会让它失效**，脚本靠接口字段判断，字段变了需要更新代码。
- 单账号。同一账号在多台设备同时用仍会互踢，只是本工具会退避，不会无限循环互顶。
- 认证是**明文 HTTP**，密码以 GET 参数在校园内网传输——这是网关协议决定的，不是本工具的选择。

## 来源与致谢

协议细节（接口路径、`user_account` 的 `,0,` 前缀格式、运营商后缀、`wlan_user_ip` 的取法）
来自对校园网门户页面及其脚本的观察，并参考了同校项目
[TUST-Campus-Network-Auto-Login](https://github.com/gethub-15/TUST-Campus-Network-Auto-Login----Android-and-Windows-)。
本项目的代码为独立重写，没有复制其源码。

其中有两处判断逻辑在原实现上会失效，本项目已修正：

1. 门户页是 **gb2312** 编码，按 UTF-8 解码会让「注销页 / 认证成功」这类中文关键字全部匹配不上；
2. 在线列表的字段是 `online_ip` / `user_account` / `total`，**不是** `loginTime`。
   照原来的写法，明明在线也会被判成「未登录」，于是反复重复认证、把自己踢下线。
